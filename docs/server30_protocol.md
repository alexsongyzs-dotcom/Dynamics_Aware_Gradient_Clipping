# develop/lyx：30 端口服务器完整研究协议

本协议延续 `origin/lyx@0779f31` 的机制优先路线。用户于 2026-10-09 授权创建
`develop/lyx` 并使用其提供的 30 端口服务器完成训练。本文件与
`configs/campaigns/lyx_full.yaml` 在本批科学实验开始前冻结。这里的“冻结”指本地
可审计配置冻结，不是已在外部平台注册。

## 问题与停止规则

研究裁剪增益的时间排列、以及裁剪在优化器状态更新之前/之后的位置，是否对未来
训练风险和最终函数产生可重复影响。无动量 SGD 的同方向、同范数缩放与全局裁剪
在数学上相同，只用于测量校验，不作为独立因果对照。

G0 测量/恢复不通过时修复工程；G1 预测增量不通过时保留负结果并停止事件控制器
主张；G2 无重复的功能/稳定性效应时不声称因果；G3 无稳定性收益或有显著性能退化
时不扩展算法规模。完整推进包括完整记录负结果，不以修改阈值强迫门槛通过。

## 数据与资源

- 8 张 RTX PRO 5000 72GB，每张 GPU 执行一个独立配置，单模型 batch size 128。
  不采用数据并行扩大 batch，以保留跨种子/干预比较的相同优化条件。
- P1、P2 和调参使用官方训练集留出的固定 5,000 张验证图像。FashionMNIST 使用
  55,000 张训练图像，CIFAR-10 使用 45,000 张。划分种子固定为 1729。
- 确认阶段重新使用完整官方训练集（60,000 / 50,000 张），仅在冻结配置后评价官方
  测试集。不得用 test accuracy 选参数。固定诊断 probe 来自训练集。
- 使用独立运行环境；代码、协议、结果与锁定依赖保存于
  `/mnt/data/users/yuxin/workspace/DAGC-develop-lyx/`。
- 解压后的相同数据可缓存到 `/tmp/dagc-yuxin-runtime/data` 以避免共享盘 I/O；
  原始数据包、校验清单和结果保持持久保存。实际缓存路径写入冻结配置。
- 小型 CNN 的自适应均值池化使用相同 floor/ceil 窗口的显式切片归约，以支持
  CUDA 严格确定性的反向传播；不关闭确定性来绕过 G0。
- PyTorch 2.8.0 / torchvision 0.23.0 CUDA 12.8 的版本组合来自
  [官方版本安装表](https://pytorch.org/get-started/previous-versions/)。运行时仍须实际
  通过 CUDA 运算和 GPU 恢复测试；版本声明本身不替代验证。

## 阶段

| 阶段 | 内容 | 预定预算 |
|---|---|---|
| P0 / G0 | CPU/CUDA 测试、真实模型测量校验、含随机增强/dropout 的逐位恢复、冻结增益回放 | 6 个 16-step 模型检查，加测试套件 |
| P1 / G1 | FashionMNIST/CNN/SGD；CIFAR-10/ResNet-18/SGD、AdamW；学习率×阈值相图 | 156 runs，每个 20 epochs，seeds 0–1 |
| P2 / G2 | 每个家族冻结一个验证集选出的 cell；同检查点的 5 种因果干预 | 最多 30 个参考 + 150 个分支；30 epochs；seeds 100–109 |
| P3 调参 | 固定、AutoClip、AGC、AdaGC、条件事件控制器；AdamW 家族另含 StableAdamW | 每个可调方法 3 个候选×3 seeds；30 epochs；seeds 200–202 |
| P3 / G3 | 冻结参数后的独立确认 | 最多 190 runs，完整训练集、90 epochs；seeds 300–309 |
| P4 | 若 G3 通过，CIFAR-100/ResNet-34 中等规模迁移 | 基线独立调参 seeds 400–402；确认 seeds 500–509，120 epochs |
| P5 | 保存所有门槛、负结果、配置、统计表和复现身份 | 以实际完成阶段为边界，不生成未测结果 |

P1 对每个学习率包含无裁剪，以及固定阈值 0.1、0.3、1、3、10。SGD 的 LR 网格为
FashionMNIST 的 0.05/0.2/0.4/0.8 和 CIFAR-10 的 0.05/0.1/0.2/0.4/0.8；AdamW 为
0.0003/0.001/0.003/0.01。筛查使用常数 LR，后续使用各阶段声明轮数的 cosine schedule。

## G1：预测与事件稳健性

当前步之前的 loss EMA 不参与未来标签的计算。训练时定义不良事件：第 50 step 后
loss 超过 `max(5, 2.5 * previous_loss_ema)`，或出现非有限 loss/gradient/update，或
loss 超过 100。预测标签是未来 1–20 steps 是否发生事件；尾部未知阴性被删失，已
观测的终止失败仍保留为阳性。先逐 run 构造完整时序，再每 5 steps 取一行。

Base 包含训练进度、LR、loss、loss slope、梯度/更新范数、方向对齐和优化器状态
proxy；History 增加曝光 EMA、占空比、切换率、burst age、距转换时间和平均强度。
分别按 seed、完整配置、配置家族分组外推；严禁随机拆分同一 run 的 steps。

自动 G1 要求三种分组检查均有至少 10 个含双类标签的 run，run-level AUPRC 增量
均值至少 0.01，bootstrap 下界大于 0，且三个家族的平均增量均为正。2 个筛查种子
下的这些区间仅是探索性 run-level 条件摘要，不是跨随机初始化总体的确认性证明。

事件检测使用 on/off margin 0.02/0.05/0.1 与 dwell 1/3/5 的网格。对中位事件数至少
为 2 的 run，至少 75% 的 `(max_count-min_count)/median_count <= 0.5`。同时保存
block-shuffled surrogate；其分布用于人工解释，不单独充当自动因果证据。

## G2：因果分支

按验证数据冻结每家族一个 cell：优先无裁剪失败而固定裁剪可训练的 LR，再优先
非退化裁剪频率，最后按验证准确率选择。使用独立 seeds 100–109，每个 seed 一对
统计单位，不以多个 checkpoint 或 steps 增大样本数。

在 step 500 的完整检查点分叉，干预 500 steps，随后全部恢复原固定裁剪策略直至
30 epochs。五种分支：原增益回放、全局打乱、50-step 块打乱、随机门控位置、优化器
更新后的参考更新范数回放。前三种时序对照实际检验长度、多重集合、和、活跃步数。
post-update 为严格匹配参考范数，必要时允许放大并记录系数，不能把它描述为纯裁剪。

参考增益分支必须逐位复现原参考最终参数；更新范数是否匹配需要从逐步日志核验。
保留实际累计更新预算，不能把“增益多重集合匹配”说成“实际更新预算也严格匹配”。

主要结果：失败率、将失败记为 0 的验证准确率、干预末尾 50 steps 的 loss。CI 为
paired bootstrap；paired sign-flip 检验后，对整个预声明比较族作 BH 校正。G2 需至少
10 个完整 pairs，校正 p < 0.05，95% CI 超出预设无效区间，并在至少两个家族中对同一
干预/结果同方向重复。无效区间为 accuracy ±0.005、loss ±0.02、失败率 ±0.1。

功能终点另报验证集预测分歧、训练 probe 的 symmetric KL、CKA、ECE 和线性插值
损失障碍。参数距离只是诊断。ResNet 的插值障碍未重新校准 BN 统计，不能单独解释
为不同 basin 的证据；Hessian power iteration 给出最大模特征值，不能无条件套用
所有优化器的稳定性边界 2。

## G3 与迁移

只有 G1/G2 通过才冻结预测器。单独增量验证每个历史信号在三个留出家族中的效应，
仅保留同号为正的前 1–2 个信号；若无信号合格，停止控制器阶段。风险模型只在 P1
拟合，推理使用截至 t-1 的历史。风险概率触发两态滞回，并使用运行分位数决定尺度；
唯一调参轴是 aggressiveness 的 0.25/0.5/0.75。

基线和候选方法都使用 3 个候选、3 个独立校准 seeds，以失败率优先、验证准确率
次之选参数。无裁剪只有一个设置，不虚构无意义的调参次数。固定阈值候选为选定
参考值的 1/3、1、3 倍；其余候选见 YAML。StableAdamW 仅在 AdamW 家族中比较。

G3 相对 tuned fixed 与校准集选出的最强自适应基线，同时要求：accuracy 的 CI 下界
> -0.005、loss 的 CI 上界 < +0.02；至少一项稳定性改善达到预设幅度并通过多重比较
校正。稳定性幅度为失败率下降 0.1 或不良事件均值减少 1；至少两个家族通过才扩大。

P4 使用 CIFAR-100/ResNet-34、120 epochs；风险模型及事件控制器 aggressiveness
迁移时保持冻结，基线重新得到相同的有限调参预算。规模结果为迁移证据，不冒充
ImageNet 或语言模型验证。

## 执行和恢复

```bash
python scripts/run_research_campaign.py \
  --protocol configs/campaigns/lyx_full.yaml \
  --output results/lyx_full_20261009 \
  --data-dir data --gpus 0 1 2 3 4 5 6 7 --execute
```

每个运行保存 manifest、配置 hash、逐步 JSONL、summary 和检查点；总进度位于
`status.json` 和 `campaign_events.jsonl`。命令退出后重新运行同一命令可复用已完成
结果并恢复未完成运行。失败的训练是科学结果，失败的进程是基础设施错误，两者
分别记录。检查点之后的残余日志会保存为 `.bak`，再从检查点对应位置恢复。

更改任何科学配置或代码必须使用新 campaign 输出目录。环境重建不应改变已冻结
依赖。控制器不会因为程序到达某个阶段便被宣称有效；最终报告以实际门槛证据为准。
